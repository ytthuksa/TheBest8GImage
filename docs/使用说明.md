# Qwen-Image-2.1 本地出图 —— 使用说明

本机有两套前端，**日常用第一套**：

| | 出图台（推荐） | ComfyUI 原生界面 |
|---|---|---|
| 打开方式 | 双击 `启动出图台.bat` | 双击 `启动ComfyUI.bat` |
| 地址 | http://127.0.0.1:8190 | http://127.0.0.1:8188 |
| 特点 | 中文、三档一键出图、自带历史画廊、Ollama 润色 | 能改工作流结构、加节点 |
| 适合 | 出图 | 调试 / 改工作流 |

两套共用同一个 ComfyUI 后端（8188），可以同时开着，**但不要同时提交任务**（8GB 显存扛不住两个任务）。

---

# 一、出图台（日常用这个）

## 1. 启动

双击 **`启动出图台.bat`**。

它会自动完成五件事（控制台上会打印 `[1/5]`~`[5/5]`）：

1. **[1/5]** 检查 Ollama 在不在（润色用，不在会自动拉起）；
2. **[2/5] 清理显存** —— 把 Ollama 驻留的模型卸载掉（2026-10-02 新增，见第二节第 5 条）；
3. **[3/5]** 检查 ComfyUI 后端（8188）—— 先做 **HTTP 体检**：端口在监听 ≠ 服务活着，
   僵死进程会被**自动清掉**，然后才启动（首次加载模型约 30 秒）；
4. **[4/5]** 启动出图台服务（8190）；
5. **[5/5]** 等端口就绪后**自动打开浏览器**。

会弹出两个**最小化**的控制台窗口（`ComfyUI 后端` / `Qwen21 出图台服务`），**别关它们**，关了服务就停了。

停止：双击 **`停止出图台.bat`**。它会先停出图台，然后问你要不要一起停 ComfyUI
（**回车 = 保留**，下次出图秒开；输入 `Y` = 一起停，释放全部显存）。

## 1.5 局域网访问（手机 / 平板出图）

`启动出图台.bat` 默认监听 `0.0.0.0`，**同一 WiFi 下的手机、平板、另一台电脑都能打开**。

地址有两个地方能看到，**不用去翻控制台**：

1. **控制台里**（启动时打印，在浏览器弹出**之前**）：
   ```
   ============================================================
     手机 / 平板访问（需连同一个 WiFi）：

          http://192.168.1.23:8190
   ============================================================
   ```
2. **网页右上角**的胶囊：`📱 手机访问 192.168.1.23:8190` —— **点一下自动复制**整条地址。

> 地址由 `_server.py` 探测本机 IP 后写进 `C:\ComfyUI\_lan_url.txt`，bat 读它来回显。
> IP 变了（换 WiFi / DHCP 重分配）会**自动更新**，不用手改。

**手机打不开？** 99% 是 Windows 防火墙没放行。右键 **`放行出图台端口.bat`** →
**以管理员身份运行**，只需做一次。

**只想本机访问**（不让局域网看到）：双击 `启动出图台-仅本机.bat`（`WEB_HOST=127.0.0.1`）。
这种模式下网页上的胶囊会**自动隐藏**，控制台也不再打印地址框。

⚠️ 局域网模式下**没有密码**，同一个 WiFi 里的任何人都能出图。别在公共 WiFi 下这么开。

## 2. 四个标签页

| 标签 | 做什么 | 输入 | 1024×1024 实测耗时 | 加速档 |
|---|---|---|---|---|
| **文生图** | 纯文字生成图片 | 提示词 + 宽高 | **~63 s** | **~30 s（2.1×）** |
| **参考图编辑** | 上传一张图，按指令改（背景/服装/姿势），**保住人脸** | 参考图 + 编辑指令 | **~186 s** | **~58 s（3.2×）** |
| **背景移除** | 上传一张图，抠掉背景 | 参考图（提示词可不动） | **~87 s** | **~56 s（1.6×）** |
| **姿势编辑** | 摆一个 3D 人偶的姿势，让参考图里的人**照做** | 参考图 + 3D 人偶姿势 | **~150 s**（实测 135~165 s） | ❌ 不支持 |

> 耗时是**墙钟总时间**（模型已热）。其中 **~17 s 是固定开销**（模型初始化 + VAE 解码 + 文本编码），
> 编辑/抠图档再多 ~15 s（参考图要过一遍 VAE 编码 + 视觉塔文本编码）。
> 真正随步数变化的是采样：**cfg 1.0 档 3.1 s/步，cfg 2.5 档 7.2 s/步**（cfg>1 时每步要跑两次模型）。
>
> **加速档**见第 3.5 节 —— 挂 viggle-turbo LoRA 后用 6 步出图，画质不降反升。详见 `LoRA加速档.md`。
> **姿势编辑档不吃加速档**（它必须挂 VNCCS 姿势 LoRA，两者会打架），所以没有加速档。

切换标签时，**参数会自动跳到该档的实测最优值**，右上角小字会提示当前配方。

## 3. 怎么填

### 提示词
- **中文可以直接写**，但模型是英文语料训练的，**英文更准**。
- 不会写英文？点 **`✨ Ollama 润色`** —— 调本机 Ollama 把中文/短句改写成完整的英文提示词。
  实测：`a cyberpunk cat` → `A sleek black cat in a neon-lit city, wearing a hacking hoodie,
  lounging on a data cable, with rainbow sparks and glitchy text in the background,
  sharp 50mm lens, harsh urban lighting, edgy and futuristic mood.`
- Ollama 没启动时**不会报错**，自动回落到离线规则增强（只补质量词，不改原意）。
- **`＋ 补质量词`**：不调模型，直接拼 `cinematic lighting, shallow depth of field...`。

### 参考图（编辑 / 抠图档）
- 点击虚线框选图，或**直接把图拖进去**。
- 上传后下方出缩略图，右上角 `×` 移除。
- 尺寸建议 ≥768px；输出尺寸**跟随参考图**（不是跟随下面的长边设置）。

### 姿势编辑档（2026-10-04 新增）

让参考图里的人**照着 3D 人偶摆姿势**（换姿势 / 换机位 / 换构图），人脸和身材照旧保住。

**用法（三步）**

1. 切到 **`姿势编辑`** 标签 → 先按平时那样**选一张参考图**（人物照）。
2. 点 **`🧊 打开姿势编辑器`** → 弹出全屏 3D 编辑器：
   - **左侧骨架库**：内置 **209 张**姿势，点一下直接套用（最快）；
   - **拖关节**：直接拖人偶的手脚/头/脊椎，实时更新；
   - **右侧机位**：可以转视角、改焦距，决定最终是正面还是侧面。
3. 点编辑器里的 **`应用`** → 回到出图台，缩略图出现 → 写提示词 → 出图。

**提示词怎么写**

| 写什么 | 别写什么 |
|---|---|
| 服装、场景、光线、镜头、质感<br>（`leather jacket, rooftop at dusk, rim light, 50mm`） | ❌ **姿势**（`standing, arms crossed, sitting`）——<br>姿势由人偶决定，写进提示词只会打架 |

**几条铁律**

- **参考图必须是全身照、正面、背景干净**。它是"换姿势"的身份来源，脸挡住或只有半身就保不住。
- **LoRA 区在姿势档里是隐藏的** —— 它会自动挂 `VNCCS_QI2_PoseStudioV1.1.safetensors`，**强度固定 1.0**（LoRA 自己的要求，改了会崩）。
- **不支持加速档**，所以耗时按原配方走（25 步 / cfg 1.0 / euler）。
- **人偶只是骨架**：它长什么样不影响出图，肤色/长相/服装全部来自参考图 + 提示词。
- 编辑器是**出图台同源代理**过来的（走 `/fisher/`）—— 所以**只能从出图台打开**，
  直接去 ComfyUI 原生界面（8188）是另一套节点式的编辑器，不通用。
- **实测显存峰值 7.32 GiB（91%）**，和另外三档（7.45 GiB / 93%）同一水位 ⇒
  **出图期间别让 Ollama 抢显存**，卡了就双击 `清理显存.bat`。
- ⚠️ **参数完全一样时会秒回上次结果**（0.3 秒"出图完成"）—— 那是 ComfyUI 的执行缓存命中，
  不是 bug。想真出图就**换个种子**。

> ✅ **2026-10-04 端到端实测通过**：参考图（站直垂手）→ 3D 人偶（张开双臂）→ 产物里同一个人
> 张开双臂，脸/发型/白 T/牛仔裤/白鞋全部保住，背景按要求换了。

### 风格预设（2026-09-30 新增）

负向词下面有个 **`风格预设`** 下拉，**17 条纯提示词风格**（胶片 / 二次元 / 杂志 / 宝丽来 /
水墨 / 水彩 / 线稿 / CG / 复古科幻 / 梦幻 …）。

- **不需要下任何 LoRA**，选中就把风格块加到你提示词的**最前面**。
- 下拉下面**实时显示**这个风格实际会加进去的那段词 —— 不用猜。
- 右上角 **`显示成人向`** 控制成人向风格是否出现在下拉里（**默认已勾选**，2026-10-02 改）。
- **和加速档可以叠加**（推荐：既有风格又快，约 50s）。
- **抠图档没有这个下拉** —— 抠图的提示词是固定指令，套风格块会把抠图指令冲掉。

实测：**17 条全部生效**。其中 4 条（胶片 / 二次元 / 杂志 / 宝丽来）做过 **3 种子命中率测试 = 100%**
（含 Z-Image 当年必须挂 LoRA 才出得来的**二次元**）。
详细清单、实测数据、写风格块的铁律见 **`风格模板.md`**。

⚠️ 其余 13 条是**单主体 × 单种子**的单点验证（13/13 通过）—— 证明「有效」，不证明「稳定」。
⚠️ **`3D CG 渲染` 最弱且依赖主体** —— 主体本身已经是渲染感时，风格块会被淹没。
自测方法见 `风格模板.md` 第五节。

### 参数
| 参数 | 说明 |
|---|---|
| 采样步数 | cfg 1.0 档 **15 步就够**；cfg 2.5 档**必须 20 步**（15 步会严重欠曝） |
| CFG | 1.0 = 不引导（快、适合文生图/抠图）；2.5 = 强引导（复杂编辑必需） |
| 采样器 | `res_multistep`（默认，比官方 euler **少 40% 的步数**，墙钟快 ~22%） |
| 随机种子 | `-1` = 每次随机；固定数字 = 可复现。出好图后记下种子改微调 |
| 出图后自动释放显存 | **默认不勾**（2026-10-02 改）。同档位连续出图保持不勾最快；换档位 / 上大分辨率前再勾上 |

## 3.5 LoRA 与加速档（2026-09-29 新增）

参数区顶部有个 **`LoRA`** 下拉：

| 选项 | 说明 |
|---|---|
| `不使用（底座原味）` | 默认。走原来的 15 / 20 步配方 |
| **加速 LoRA** → `viggle-turbo v0.2.1 r128` | **推荐**。选中后「加速档」自动勾上 |
| `viggle-turbo v0.1 r64` | 旧版对照，官方原话「没有理由优先它」，只有 4 步档 |
| 其他 LoRA | 归在「其他 LoRA（合并进权重）」分组，走经典采样 |

### 加速档预设（步数档）

勾上「加速档」后，下面会出现 **`加速档预设`** 下拉 —— 这是**官方给的一整套 sigma 表**，
步数和表是一体的，所以只能从这 5 档里选：

| 预设 | 什么时候用 |
|---|---|
| **`6 步 · 官方推荐`** | **默认**。v0.2.1 标准档，0% 布局漂移 |
| **`8 步 · 密集文字`** | **画面里要出文字**（招牌 / 海报 / 字幕）时选它，小字明显更干净 |
| `7 步` | 0% 漂移、略锐，官方说「不比 6 步明显更好」 |
| `5 步 · 启动 schedule` | v0.2 发布时的档，约 4% 提示词布局会漂，官方不建议再选 |
| `4 步 · 训练 schedule` | 学生模型的训练档，细节和多样性略低。v0.1 r64 只能用这档 |

实测 6 步 vs 8 步（同提示词同种子，霓虹招牌 `MOTEL 24H OPEN`）：
两张**拼写都正确**，8 步的灯管内部结构和湿沥青颗粒明显更细，**细节量 +44%**（Laplacian 方差 1075.9 vs 747.4）。

### 加速档会锁住哪些控件

选中加速 LoRA 并勾上「加速档」后，**步数 / CFG / 采样器 / 调度器会自动置灰** ——
这一档由 LoRA 接管，调它们没用：

- **CFG 和负向词完全不生效**。加速档走单次模型调用（无 classifier-free guidance），负向词根本没参与采样。
  要压制某些内容只能改正向提示词。这是 LoRA 的设计决定的，不是 bug。
- **采样器固定 `euler`**，**调度器固定 viggle sigma 表**。它是 DMD 蒸馏的少步模型，
  换成 KSampler 自带 scheduler 会「过拟合锐利」，画面脏、颗粒重。
- **步数只能从上面 5 档预设里选**。要加/减步数只能动高噪声端，
  低噪声端 `0.875, 0.75, 0.5, 0.25` 是训练落点，必须保留。

### 实测（1024×1024，热态墙钟）

| | 基线 | 加速档 | 加速比 | 细节量 |
|---|---|---|---|---|
| 文生图 | 63.1 s / 15 步 | **30.1 s / 6 步** | **2.10×** | 786 vs 526（**更锐**） |
| 参考图编辑 | 188.6 s / 20 步 | **58.2 s / 6 步** | **3.24×** | 686 vs 433（更锐） |
| 背景移除 | ~87 s / 15 步 | **56.1 s / 6 步** | ~1.55× | 掩膜 IoU 0.9857 |

对照实验：同种子同提示词，**6 步但不挂 LoRA** → 细节量只有 255（糊、塑料感）。
挂了 LoRA 是 786。证明 LoRA 真的在生效。

### LoRA 权重

- **viggle-turbo 保持 `1.0`**，官方明确要求。
- 普通 LoRA 按需调，风格 LoRA 常用 `0.6~0.9`。

### 自己加 LoRA

把 `.safetensors` 丢进 `C:\ComfyUI\models\loras\`，**重启出图台**（后端启动时扫目录），刷新页面即可。
⚠️ 必须是 **Qwen-Image-2.1 架构**的 LoRA。Z-Image 那 47 个 LoRA 挂不上（隐藏维 3840 vs 4096，结构不匹配）。

> 完整技术说明、原理、排障见同目录 **`LoRA加速档.md`**。

# 二、8GB 显存铁律（踩过的坑）

1. **同档位连续出图不要释放显存** —— 模型复用，第二次明显更快。
2. **换档位 / 上 1280+ 分辨率前，先点「释放显存」**（或取消自动释放的勾，手动控制）。
3. **1536 能跑，但余量只剩 ~500MB**。⚠️ 峰值显存看不出问题（由文本编码器权重决定，几乎不随分辨率变），
   只有 `s/it` 突然偏离线性才是出事了 —— 1280 之后紧接 1536 会让单步从 18 s 塌到 **183 s**。
4. **ComfyUI 和 Ollama 抢同一块卡**。润色走的是纯 CPU（`num_gpu=0`）+ 用完即卸（`keep_alive=0`），
   所以不占显存，**但会抢 CPU** —— 实测和编辑档并发时，耗时从 ~157 s 涨到 ~193 s。
   **要精确计时就等润色跑完再出图。**
5. ⚠️ **出图突然变慢 / 卡死（每步几分钟）= 有别的程序把模型驻留在显存里了。**
   **2026-10-02 真实事故**：`qwen3.5-9b`（5.40 GB）+ `nomic-embed-text`（0.30 GB）被
   **出图台以外的程序**持续调用、常驻显存，8 GB 卡只剩 ~5.4 GB，
   DiT(4.2 GB) + TE(5.9 GB) 装不进去 ⇒ 每步在 CPU↔GPU 之间换页，
   编辑档单步从正常的 **9.7 s 塌到 123~252 s**（整张图要 12 分钟）。

   **怎么判断**（两个特征）：
   - `nvidia-smi` 看：**GPU 占用 99%，但功耗只有 15 W**（正常满负荷是 35~44 W）；
   - 后端日志里 `s/it` 明显偏离线性（正常 6 步档 3.1 s/步）。

   **怎么修**（任选其一）：
   - 双击 **`清理显存.bat`** —— **先让 ComfyUI 卸掉自己的缓存模型**，再把 Ollama 驻留的模型卸载（`keep_alive=0`）；
   - 或者干脆**双击启动脚本** —— `启动出图台.bat` / `启动ComfyUI.bat` 现在**启动时会自动清一次显存**，
     第 `[2/5]` 步就是它（详见第一节「启动」）。

   清理后实测：功耗 15.85 W → 44.31 W，同一任务 **38.4 秒**跑完（原本估 12 分钟）。

   和第 1 条别搞混：**第 1 条是"自己别主动释放"（释放了要重新加载），第 5 条是"别人占了要抢回来"。**

6. ⚠️ **显存下不来时，先怀疑 ComfyUI 自己**（2026-10-04 踩到）。
   **症状**：`ollama ps` 是空的、GPU 利用率 0%、功耗 1.45 W —— 看着"没人占"，
   但显存就是有 **3.9 GiB 下不来**，害得一次测试白等了 5 小时。

   **判据**（一条命令）：
   ```bash
   curl --noproxy "*" -s http://127.0.0.1:8188/system_stats
   ```
   看 `torch_vram_total` —— **不为 0 就是 ComfyUI 自己攥着**（出过图之后它会一直缓存模型）。

   **怎么修**：`清理显存.bat` 现在会先调 ComfyUI 的 `/free`
   （`{"unload_models":true,"free_memory":true}`），实测 **4968 MiB → 456 MiB**。

# 六、一键释放资源（2026-10-03 新增）

出图台 + ComfyUI + Ollama 三个都吃显存。不想出图了、要跑别的东西（游戏 / 别的模型）时，
双击 **`释放资源.bat`** 就行：

| 动作 | 说明 |
|---|---|
| 按端口找进程 | 8190 / 8188 / 8200 → 查出监听 PID |
| 杀进程树 | `taskkill /F /T`，连父进程一起（否则端口不释放） |
| 卸 Ollama | 把所有驻留模型 `keep_alive=0` 卸掉 |
| **复活检测** | 等 15 秒再看一遍，**回来了就报退出码 2** |

实测：8190 + 8188 停掉后显存 **6917 → 566 MiB**。

**退出码 2 是什么意思** —— 有进程被**别的 WorkBuddy 会话**吊着（比如另一个会话正在跑
知识库索引重建），杀了会自动重启。脚本检测到这种情况会**明确告诉你**，并**主动放弃继续杀**，
免得跟别人拉锯。这种情况要么等它跑完，要么去那个会话里停。

参数（命令行直接跑 python 时）：
```
_release_resources.py --dry-run          只看会杀谁，不动手
_release_resources.py --ports 8190,8188  只处理指定端口
_release_resources.py --keep-ollama      不卸 Ollama 模型
```

# 七、端口体检（2026-10-02 新增）

## 它解决什么问题

Windows 上进程可能**已经死了，但端口还占着** —— `netstat` 里 8188 仍然显示 `LISTENING`。

老版启动脚本只看 `netstat`，于是判定「ComfyUI 已在运行」→ **跳过启动** →
浏览器打开一个永远转圈的页面。**你点几次都一样，看起来就像「怎么都起不来」。**

## 现在怎么做的

启动脚本在启动 ComfyUI 之前，先跑一次 **HTTP 体检**（探 `/system_stats`）：

| 体检结果 | 脚本动作 |
|---|---|
| 服务健康，真在跑 | 跳过启动，直接开网页 |
| 端口空闲 | 正常启动 |
| **端口被占但不响应 = 僵死** | **自动杀掉**（连它的父进程一起），然后正常启动 |
| 占着但清不掉（卡在显卡驱动里） | 明确提示你去任务管理器结束 `python.exe`，或重启电脑 |

> **安全阀**：只会清理 `python.exe`，不会误杀别的程序（比如 Ollama）。

## 为什么「杀父进程」这一步是必须的

僵死进程往往**已经死了**，`taskkill /F /PID <它>` 会报
`There is no running instance of the task` —— 杀不动。

真正吊住那个端口 socket 的，是它的**父进程**（`.venv\Scripts\python.exe` 这个启动器 stub）。
所以体检脚本在直接杀失败后，会**查出父进程 PID 再杀一次**，端口这才释放。

## 手动排查（脚本搞不定时）

```bat
:: 1. 看端口是不是被占着
netstat -ano | findstr ":8188"

:: 2. 探活（000 就是死的）
curl --noproxy "*" -m 5 http://127.0.0.1:8188/system_stats

:: 3. 看显存（已释放 + 功耗 1.4W 左右 = 确实瘫了）
nvidia-smi --query-gpu=memory.used,power.draw --format=csv,noheader
```

搞不定就直接：**任务管理器（Ctrl+Shift+Esc）→ 详细信息 → 结束所有 `python.exe`**，再重跑启动脚本。
实在不行**重启电脑**（最彻底）。
